Styling and Theme

Tailwind CSS powers styling, your styles/globals.css is compiled once into styles/koyo.css, and the whole site shares one brand color.

Tailwind integration#

The scaffold ships package.json and a Tailwind v3 tailwind.config.js. Tailwind runs through its CLI, not through a bundler:

  • Utility classes in your components and pages are scanned by Tailwind from app/, components/, and related source folders.
  • Your custom CSS lives in styles/globals.css.
  • Koyo compiles globals.css to a single styles/koyo.css that the root layout links.

Writing custom CSS#

Put component styles and global rules in styles/globals.css. The dev server rebuilds koyo.css whenever you save. The generated koyo.css is excluded from Tailwind's content scan, so utility classes you add to it do not risk a purge.

Other CSS files placed under public/ or served from the styles/ folder are passed through untouched for third-party libraries.

The brand palette#

The Koyo scaffold defines its brand color once in tailwind.config.js: 

// tailwind.config.js
theme: {
  extend: {
    colors: {
      brand: {
        DEFAULT: '#1800ad',   // Koyo indigo
        dark:    '#13008a',   // pressed / darker
      },
    },
  },
},

Use it anywhere Tailwind accepts a color, for example bg-brand, text-brand, and border-brand. The page <meta name="theme-color" content="#1800ad"> in the root layout matches, so browser chrome tints with the brand.

Animation utilities#

The scaffold includes a few tasteful keyframes in styles/globals.css:

  • koyo-fade-up: fade in and rise, used by the landing hero.
  • koyo-float: a gentle vertical float for the hero icon.
  • koyo-glow: a soft brand glow behind the hero tile.

They are plain CSS animations, so anything can opt into them.

Static assets#

Everything in public/ is served at the site root: images, favicons, fonts. Introspect the bundled assets that the scaffold copies into public/ for the app icon, logo, favicon, manifest, and apple touch icon.
