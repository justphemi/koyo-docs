Development Tooling

The dev server is designed to be quiet and fast: local and network URLs, automatic browser reload, and logs that stay out of your way until you ask for them.

Starting the server#

koyoapp dev

The startup block tells you where the app is reachable:

Koyo dev server running
  Local:   http://127.0.0.1:2309
  Network: http://192.168.1.42:2309

The port resolution order is the --port flag, then PORT in koyo.config.py, then the default 2309. The default bind is 0.0.0.0 so devices on your LAN work; pass --host 127.0.0.1 to restrict to localhost.

Watch and hot reload#

These paths are watched and any change reloads or recompiles:

  • app/ and components/ (Python modules).
  • public/ (static files).
  • styles/ (Tailwind rebuild).
  • koyo.config.py and tailwind.config.js.

The browser auto-reloads through a polling endpoint (/__koyo-reload) guarded by a token stored in .koyo/reload-token. Python bytecode cache is redirected to .koyo/pycache so __pycache__ never appears in your source tree.

Logs and verbose mode#

  • By default logs stay quiet. The console shows a summary, and detail is written to .koyo/dev-server.log and .koyo/tailwind.log.
  • Pass --verbose to stream the full request and rebuild logs to the terminal.
  • The same flag exists on add, remove, and install for a glanceable explanation of each step.

Errors in development#

Set KOYO_DEV=1 in the environment to enable the interactive debug error page. It shows the failing Python traceback and the request details, so template errors are visible right in the browser. Without KOYO_DEV, errors return a generic internal server error and the traceback stays in the log.

koyo.config.py#

PROJECT_NAME = "my-app"
PORT = 2309

The config file marks a directory as a Koyo project and is read for defaults by the CLI and the dev server.
