Dependencies

The koyoapp CLI owns pyproject.toml for you. Add a package, remove one, or install everything into a fresh virtual environment.

How the CLI models dependencies#

Dependencies live in pyproject.toml: 

[project]
dependencies = [
    "requests==2.31.0",
]

[project.optional-dependencies]
dev = [
    "pytest==7.4.0",
]

The CLI writes with tomlkit, so your formatting and comments survive every edit. There is no lock file; pip resolves the declared ranges at install time.

Adding packages#

koyoapp add requests
koyoapp add "fastapi>=0.100"
koyoapp add black --dev
koyoapp add httpx pytest --dev
  • Without a specifier, the installed version is pinned exactly, for example requests==2.31.0.
  • Hand a specifier and it is kept as written, such as fastapi>=0.100.
  • --dev routes to the dev optional group instead of runtime dependencies.
  • Multiple packages can be added in one command.
  • The package is installed after the entry is written.
  • Adding a package that is already declared updates the existing line instead of duplicating it.

Removing packages#

koyoapp remove requests
koyoapp remove pytest --dev
  • The entry is removed from both the runtime and dev arrays, then the package is uninstalled.
  • Removing a package that is not present prints an informational message instead of failing.

Installing everything#

koyoapp install
koyoapp install --no-dev    # runtime only
koyoapp install --clean     # recreate the virtual environment first
  • A .venv is created automatically when one is missing.
  • Installation batches the dependencies instead of one pip call at a time.
  • --no-dev skips the dev group.
  • --clean deletes the existing .venv before installing.

Project recognition#

The dependency commands expect to run inside a Koyo project. A project is recognized by the presence of koyo.config.py; running outside one stops with a clear error telling you to cd into the project directory first.
